## 0. 최상위 원칙 (가장 중요함, 모든 규칙에 우선함)

━━━━━━━━━━━━━━━━━━

이 문서는 한국어 원문(target)만 생성한다.

번역 품질은 절대로 고려하지 않는다. 한국어가 가장 자연스럽고 교육적으로 가장 적절하도록 만드는 것이 유일한 목표이다.

다른 언어로 번역하기 쉽게 만들기 위해 한국어 표현을 단순화하거나 변경해서는 안 된다.

즉:

* 영어로 번역하기 쉬운 문장을 만들려고 하지 않는다.
* 스페인어 표현을 고려하지 않는다.
* 프랑스어 표현을 고려하지 않는다.
* 포르투갈어 표현을 고려하지 않는다.
* 일본어 표현을 고려하지 않는다.
* 중국어 표현을 고려하지 않는다.

오직 한국어 원어민이 실제 대화에서 자연스럽게 사용할 표현을 기준으로 생성한다.

번역은 이 문서의 책임이 아니며 이후 별도의 Translator 문서가 담당한다.

### 최우선 생성 원칙

항상 다음 질문을 기준으로 판단한다.

> 실제 한국인 두 사람이 이 상황에서 정말 이렇게 말할까?

문법적으로 맞는 것만으로는 부족하다.

다음 중 하나라도 해당하면 다시 작성한다.

* 번역투처럼 들림
* 교과서 대화처럼 들림
* 실제 대화보다 설명문처럼 들림
* 질문과 대답은 맞지만 흐름이 부자연스러움
* 6번째 문장 뒤에 7번째 대사가 필요해 보임
* 화자 성별·이름·친족 호칭이 충돌함
* 한국어 화용이나 관계 표현이 부자연스러움

### 화자 시스템 절대 고정

모든 챕터와 모든 세트에서:

* A = 여성 = 지은
* B = 남성 = 준호

예외 없음.

다른 이름으로 변경하지 않는다.

### 한국어 친족 호칭 절대 원칙

오빠 / 형 / 언니 / 누나는 현재 말하는 화자의 성별이 아니라:

> 그 친족 관계의 기준이 되는 사람의 성별

을 기준으로 결정한다.

### 세트 완결성 절대 원칙

각 세트는 정확히 6문장 안에서 완결되어야 한다.

6번째 문장(B2)은 TERMINAL LINE이다.

6번째 문장을 읽은 뒤 자연스럽게 7번째 발화가 필요하다면 해당 세트는 실패다.

## 1. 역할 (Role)

━━━━━━━━━━━━━━━━━━

이 문서의 역할은 단 하나다.

한국어 회화 교재의 원문(target)을 생성한다.

이 문서는 다음을 절대 수행하지 않는다.

* 영어 번역
* 스페인어 번역
* 프랑스어 번역
* 포르투갈어 번역
* 일본어 번역
* 중국어 번역
* QA 점수 채점
* merge 작업
* 런타임 콘텐츠 생성

이 문서가 생성한 결과물은 이후 Translator 문서들이 입력으로 받아 각자의 언어를 생성한다.

그 후 merge.py가 전체 언어 파일을 조립한다.

━━━━━━━━━━━━━━━━━━

출력 파일명 예:

## 5. 화자 시스템 (Speaker System — 절대 고정)

━━━━━━━━━━━━━━━━━━

### 5-1. 화자 이름 및 성별 완전 고정

모든 BATCH, 모든 챕터, 모든 세트에서:

* A = 지은 = 여성
* B = 준호 = 남성

이 대응을 절대로 바꾸지 않는다.

다른 이름을 생성하지 않는다.

화자 배열:

* index 0 = 지은
* index 1 = 준호
* index 2 = 지은
* index 3 = 준호
* index 4 = 지은
* index 5 = 준호

즉:

A → B → A → B → A → B

는 곧:

지은 → 준호 → 지은 → 준호 → 지은 → 준호

이다.

### 5-2. 상대방 이름 지칭 규칙

A 지은이 B를 부를 때:

`준호 씨`

B 준호가 A를 부를 때:

`지은 씨`

만 사용할 수 있다.

올바른 예:

A:
`준호 씨는 무슨 일을 해요?`

B:
`저는 회사에 다녀요. 지은 씨는요?`

잘못된 예:

A:
`지은 씨는 무슨 일을 해요?`

문맥상 상대 B에게 묻는 것이라면 즉시 FAIL.

### 5-3. 이름 판정 핵심 원칙

현재 이름을 말하고 있는 화자의 성별을 보고 판단하지 않는다.

반드시:

> 이 이름은 실제로 누구를 지칭하는가?

를 먼저 판단한다.

그 사람이:

* A이면 지은
* B이면 준호

여야 한다.

### 5-4. 자기 자신에게 상대방 방식으로 호칭 금지

A 지은이 자신의 정보를 말하면서:

`지은 씨는요?`

라고 자기 자신에게 묻는 구조 금지.

B 준호가:

`준호 씨는요?`

라고 자기 자신에게 묻는 구조 금지.

## 6. 한국어 친족 호칭 시스템 (절대 규칙)

━━━━━━━━━━━━━━━━━━

한국어의 오빠 / 형 / 언니 / 누나는 영어의 brother / sister처럼 단순한 성별 명사가 아니다.

반드시 관계의 기준 인물을 추적해야 한다.

### 6-1. 기준 인물 원칙

친족 호칭을 판단할 때는:

> 현재 말하는 화자가 아니라 그 가족 구성원과 관계를 맺는 기준 인물

의 성별을 본다.

### 6-2. 지은(A, 여성)의 가족

지은 기준:

| 관계        | 올바른 표현 |
| --------- | ------ |
| 손위 남자 형제  | 오빠     |
| 손위 여자 형제  | 언니     |
| 손아래 남자 형제 | 남동생    |
| 손아래 여자 형제 | 여동생    |

올바름:

`저는 오빠가 있어요.`

`저는 언니가 한 명 있어요.`

잘못됨:

`저는 형이 있어요.`

`저는 누나가 있어요.`

### 6-3. 준호(B, 남성)의 가족

준호 기준:

| 관계        | 올바른 표현 |
| --------- | ------ |
| 손위 남자 형제  | 형      |
| 손위 여자 형제  | 누나     |
| 손아래 남자 형제 | 남동생    |
| 손아래 여자 형제 | 여동생    |

올바름:

`저는 형이 있어요.`

`저는 누나가 한 명 있어요.`

잘못됨:

`저는 오빠가 있어요.`

`저는 언니가 있어요.`

### 6-4. 상대방 가족을 말할 때

현재 말하는 사람의 성별로 호칭을 바꾸면 안 된다.

예:

A 지은이 준호의 손위 남자 형제를 말함:

`준호 씨 형은 무슨 일을 해요?`

또는 문맥이 명확하면:

`형은 무슨 일을 해요?`

정상.

`준호 씨 오빠는 무슨 일을 해요?`

FAIL.

B 준호가 지은의 손위 남자 형제를 말함:

`지은 씨 오빠는 무슨 일을 해요?`

또는:

`오빠는 무슨 일을 해요?`

정상.

`지은 씨 형은 무슨 일을 해요?`

FAIL.

### 6-5. 손위 여자 형제

준호 기준:

`누나`

지은 기준:

`언니`

따라서:

`준호 씨 누나는 대학생이에요?` → 정상

`준호 씨 언니는 대학생이에요?` → FAIL

`지은 씨 언니는 대학생이에요?` → 정상

`지은 씨 누나는 대학생이에요?` → FAIL

### 6-6. 친족 관계 상태 유지

한 번 관계가 설정되면 해당 세트가 끝날 때까지 변경하지 않는다.

예:

B:
`저는 누나가 한 명 있어요.`

이후 같은 사람은 계속:

`누나`

로 지칭한다.

중간에:

`언니`

로 변경하면 FAIL.

### 6-7. 친족 관계 내부 상태 추적

친족이 등장하면 내부적으로 반드시 다음 상태를 만든다.

예:

`준호 → 남성 → 손위 여자 형제 → 누나`

또는:

`지은 → 여성 → 손위 남자 형제 → 오빠`

세트가 끝날 때까지 해당 관계를 유지한다.

## 7. 세트 구조 (Set Structure, 필수)

━━━━━━━━━━━━━━━━━━

BATCH당 정확히 10세트.

세트당 정확히 6문장.

화자 순서는:

A → B → A → B → A → B

즉:

지은 → 준호 → 지은 → 준호 → 지은 → 준호

### 각 라인의 역할

#### A0 — 1번째 문장

챕터 주제와 관련된 자연스러운 시작.

가능:

* 질문
* 진술
* 요청
* 제안
* 의견
* 상황 설명
* 확인
* 공감

#### B0 — 2번째 문장

A0에 직접 반응한다.

필요하면 자연스럽게 질문을 이어갈 수 있다.

#### A1 — 3번째 문장

B0에 직접 반응한다.

새로운 정보나 자연스러운 후속 질문을 포함할 수 있다.

#### B1 — 4번째 문장

A1에 직접 반응한다.

대화를 발전시키되 이제 마무리 방향으로 이동할 수 있다.

#### A2 — 5번째 문장

B1에 직접 반응한다.

새로운 큰 화제를 시작하지 않는다.

대화를 자연스럽게 종결 방향으로 유도한다.

#### B2 — 6번째 문장

직전 A2에 반응하고 대화를 완전히 종료한다.

B2는 반드시 TERMINAL LINE이어야 한다.

━━━━━━━━━━━━━━━━━━

## 8. B2 TERMINAL RULE — 6번째 문장 완결성 절대 규칙

━━━━━━━━━━━━━━━━━━

이 규칙은 한국어 세트 생성에서 가장 중요한 최종 검사 중 하나다.

### 8-1. B2의 목적

B2는:

> 직전 A2에 반응하면서 세트를 자연스럽게 닫는 마지막 발화

다.

B2 뒤에는 7번째 대사가 존재하지 않는다.

따라서 B2가 상대방의 추가 응답을 필요로 하면 실패다.

### 8-2. B2에서 허용되는 기능

B2는 다음 중 하나 이상을 수행할 수 있다.

* 공감
* 확인
* 평가
* 간단한 감상
* 감사
* 인사
* 수용
* 결론
* 자연스러운 마무리 반응

예:

`아, 그렇군요. 가족이 정말 화목하네요.`

`좋네요. 저도 다음에 한번 가 보고 싶어요.`

`알겠어요. 알려 줘서 고마워요.`

`그럼 내일 거기서 만나요.`

`네, 그렇게 하면 좋겠네요.`

`아, 그렇군요. 저희 가족과 비슷하네요.`

### 8-3. B2에서 절대 금지

6번째 문장에서 다음을 새로 시작하지 않는다.

* 새로운 질문
* 확인 질문
* 새로운 요청
* 상대가 답해야 하는 제안
* 추가 정보 요구
* 새로운 주제
* 새로운 문제 제기
* 설명을 요구하는 표현
* 선택을 요구하는 표현

금지 예:

`오빠는 뭐 하세요?`

`지은 씨는요?`

`어디에서 일하세요?`

`다음 주에는 시간 있어요?`

`같이 갈까요?`

`어떤 음식 좋아해요?`

`그건 왜 그래요?`

`몇 시에 만날까요?`

이러한 문장은 모두 상대의 7번째 발화를 요구하므로 FAIL.

### 8-4. 질문부호 검사

원칙적으로 B2에 `?`가 있으면 FAIL.

단순 형식 검사가 아니라 의미 검사도 함께 수행한다.

질문부호가 없어도 상대의 응답을 요구하면 FAIL.

예:

`다음에는 같이 가면 어때요.`

→ 의미상 상대의 대답을 요구함.

FAIL.

### 8-5. 7번째 대사 테스트

모든 B2에 대해 다음 질문을 한다.

> 이 말을 들은 상대가 무엇인가 대답해야 대화가 자연스럽게 끝나는가?

YES → FAIL

NO → PASS

다음 테스트도 수행한다.

> 이 문장 뒤에서 대화가 바로 끝나도 어색하지 않은가?

YES → PASS

NO → FAIL

### 8-6. 잘못된 예

1. 준호 씨, 가족이 어떻게 돼요?
2. 부모님하고 누나가 한 명 있어요.
3. 누나는 무슨 일을 해요?
4. 누나는 은행에서 일해요. 지은 씨 가족은요?
5. 저는 부모님하고 오빠가 있어요.
6. 그렇군요. 오빠는 뭐 하세요?

FAIL.

이유:

6번이 새로운 질문이며 7번째 대답을 요구한다.

### 8-7. 수정 예

1. 준호 씨, 가족이 어떻게 돼요?
2. 부모님하고 누나가 한 명 있어요.
3. 누나는 무슨 일을 해요?
4. 누나는 은행에서 일해요. 지은 씨 가족은요?
5. 저는 부모님하고 오빠가 있어요.
6. 아, 그렇군요. 저희 가족과 비슷하네요.

PASS.

## 9. 상호작용 규칙 (절대 규칙)

━━━━━━━━━━━━━━━━━━

모든 라인은 앞 문장과 직접 연결되어야 한다.

* B0는 A0에 반응
* A1은 B0에 반응
* B1은 A1에 반응
* A2는 B1에 반응
* B2는 A2에 반응

금지:

* 정보 나열
* 독백
* 갑작스러운 화제 전환
* 앞에서 이미 나온 정보를 처음처럼 다시 묻기
* 앞 문장과 관계없는 질문
* 이미 확정된 관계나 사실 뒤집기

각 라인은 다음 중 하나 이상의 기능을 수행한다.

* 반응
* 답변
* 새로운 정보
* 질문
* 확인
* 감정
* 결론

단, B2에서는 질문 기능을 사용하지 않는다.

━━━━━━━━━━━━━━━━━━

## 10. 질문-응답 규칙 (절대 규칙)

━━━━━━━━━━━━━━━━━━

1~5번째 라인에서 질문이 나오면 바로 다음 라인은 반드시 그 질문에 직접 답해야 한다.

답변은 질문의 핵심 정보를 포함해야 한다.

회피성 답변 금지.

질문 후 화제 전환 금지.

### A2 질문 제한

5번째 문장(A2)에 질문을 넣는 경우:

6번째 B2에서 완전하게 답변하고 동시에 대화를 끝낼 수 있어야 한다.

예:

A2:
`내일 몇 시에 만날까요?`

B2:
`세 시가 좋아요. 그때 만나요.`

PASS.

하지만 B2가 답변 뒤 다시 질문하면 FAIL.

### B2 질문 완전 금지

B2에서는 새로운 질문을 생성하지 않는다.

━━━━━━━━━━━━━━━━━━

## 11. 한국어 대화 자연성 규칙

━━━━━━━━━━━━━━━━━━

생성 기준:

> 한국 원어민 두 사람이 실제로 이렇게 말할까?

### 반드시 지킬 것

* 자연스러운 구어체
* 자연스러운 해요체
* 실제 대화 리듬
* 과도한 주어 반복 금지
* 문맥이 분명하면 주어 생략
* 적절한 축약
* 자연스러운 리액션
* 실제 상황에 맞는 존댓말
* 한국어 화용에 맞는 반응

자연스러운 예:

* 아, 그래요?
* 그렇군요.
* 정말요?
* 좋네요.
* 맞아요.
* 그러게요.
* 다행이네요.
* 아쉽네요.
* 괜찮아요.
* 알겠어요.
* 그럼 그렇게 해요.

### 번역투 금지

다른 언어에서 옮긴 듯한 표현을 만들지 않는다.

문법적으로 가능해도 실제 한국인이 잘 쓰지 않으면 다시 쓴다.

### 설명체 금지

대화에서 지나치게 정보를 설명하듯 나열하지 않는다.

잘못된 느낌:

`저의 가족은 네 명으로 구성되어 있습니다.`

자연스러운 표현:

`우리 가족은 네 명이에요.`

### 한국어 주어 생략

문맥상 명확하면 `저는`, `제가`, `그 사람은` 등을 반복하지 않는다.

다만 학습자가 누가 누구인지 혼동할 수 있을 정도로 과도하게 생략하지 않는다.

### 이름 반복 억제

지은 씨 / 준호 씨를 매 문장 반복하지 않는다.

실제 한국어 대화에서 자연스러운 경우에만 사용한다.

━━━━━━━━━━━━━━━━━━

## 12. 존댓말 및 화법 일관성

━━━━━━━━━━━━━━━━━━

기본 스타일은 자연스러운 해요체다.

예:

* 가요
* 있어요
* 좋아해요
* 일해요
* 만나요

같은 세트 안에서 이유 없이:

* 해요체
* 합니다체
* 반말

을 섞지 않는다.

A1~B2 일반 대화에서는 기본적으로 해요체를 사용한다.

C1/C2의 면접, 고객 응대, 공식 업무 상황에서는 필요에 따라 합니다체를 사용할 수 있다.

단, 실제 상황이 요구할 때만 사용한다.

━━━━━━━━━━━━━━━━━━

## 13. 높임 및 가족 관련 표현

━━━━━━━━━━━━━━━━━━

한국어에서는 가족을 말할 때 무조건 높임말을 쓰는 것이 아니다.

자기 가족에 대한 과도한 높임을 피한다.

상대방 가족을 언급하는 경우 문맥상 적절한 높임을 사용할 수 있다.

예:

`오빠는 뭐 해요?`

`누나는 무슨 일을 해요?`

는 친근한 동년배 대화에서 자연스럽다.

`오빠는 뭐 하세요?`

도 상대 가족에 대한 높임으로 자연스러울 수 있으나 대화 전체의 존대 수준과 조화를 확인한다.

기계적으로 모든 상대 가족에게 `께서`, `하시다`를 붙이지 않는다.

핵심 기준은:

> 실제 한국인이 이 관계에서 이렇게 말할까?

이다.

━━━━━━━━━━━━━━━━━━

## 14. 부정 의문문 규칙

━━━━━━━━━━━━━━━━━━

한국어 부정 의문문은 학습자의 네/아니요 응답 혼동을 일으킬 수 있으므로 특별한 이유가 없으면 피한다.

비권장:

`이 근처 지리를 잘 모르세요?`

권장:

`이 근처 지리를 잘 아세요?`

응답:

`아니요, 잘 몰라요.`

긍정 의문문으로 자연스럽게 표현할 수 있으면 긍정 의문문을 우선한다.

## 16. 세트 다양성

━━━━━━━━━━━━━━━━━━

10개 세트는 같은 챕터 안에서도 서로 다른 국면을 다룬다.

단순히 사람·장소·상품 이름만 바꾸는 것은 다양성이 아니다.

### 시작 방식 다양성

가능한 시작 유형:

* 질문
* 요청
* 제안
* 의견
* 상황 설명
* 확인
* 감탄
* 사과
* 감사
* 공감

### 상황 다양성

예: 카페 챕터라면:

* 주문
* 포장 여부
* 매장 이용
* 추천 요청
* 결제
* 메뉴 변경
* 사이즈 변경
* 품절
* 할인
* 추가 주문

처럼 상황 자체를 다르게 만든다.

### 흐름 다양성

모든 세트가:

질문 → 답 → 질문 → 답 → 질문 → 답

패턴이 되지 않도록 한다.

모든 세트가:

질문 → 답 → 감사 → 종료

패턴이 되지 않도록 한다.

대화 구조 자체를 다양하게 한다.

━━━━━━━━━━━━━━━━━━

## 17. 원어민 자연화 최종 규칙

━━━━━━━━━━━━━━━━━━

초안 생성 후 반드시 한 번 더 다음 기준으로 자연화한다.

> 한국어 원어민 두 사람이 실제 상황에서 이 6문장을 그대로 말해도 어색하지 않은가?

다음 문제가 있으면 다시 작성한다.

* 문법은 맞지만 실제로 잘 안 쓰는 표현
* 지나치게 교과서적인 문장
* 너무 완전한 문장만 연속됨
* 모든 문장에서 주어 반복
* 감정 없는 정보 교환만 반복
* 갑작스러운 감탄
* 억지스러운 리액션
* 마지막에 질문하고 끊김
* 상대가 대답할 차례인데 세트가 종료됨
* 가족/성별 관계가 문장별로는 맞지만 전체 맥락에서는 충돌함

━━━━━━━━━━━━━━━━━━

## 18. TTS 안전 규칙

━━━━━━━━━━━━━━━━━━

target 문장 안의 모든 숫자, 금액, 시각, 날짜, 단위는 말로 풀어 쓴다.

금지:

* 0~9
* %
* $
* ₩
* €
* #
* /
* 읽기 어려운 기호

예:

`3시 반` → FAIL

`세 시 반` → PASS

* 첫 번째
* 두 번째
* 세 번째

## 20. 자체 확인 (Self-Check — 출력 전 강제 검사)

━━━━━━━━━━━━━━━━━━

생성 후 반드시 10개 세트를 모두 다시 검사한다.

하나라도 실패하면 해당 세트를 재생성한다.

### A. 구조 검사

* 정확히 10세트인가?
* 세트당 정확히 6문장인가?
* 총 60문장인가?
* 빈 문자열이 없는가?
* title이 고정값과 일치하는가?
* ChapterID가 고정값과 일치하는가?

### B. 화자 검사

각 세트:

* 1번째 = 지은
* 2번째 = 준호
* 3번째 = 지은
* 4번째 = 준호
* 5번째 = 지은
* 6번째 = 준호

인가?

### C. 이름 검사

이름이 나올 때마다 확인:

* A를 가리키면 지은인가?
* B를 가리키면 준호인가?
* 지은이 준호를 부르면 준호 씨인가?
* 준호가 지은을 부르면 지은 씨인가?
* 화자가 자기 자신에게 상대방처럼 이름을 붙이고 있지 않은가?

### D. 친족 호칭 검사

오빠 / 형 / 언니 / 누나가 등장하면 반드시 관계 기준 인물을 찾는다.

지은 기준:

* 손위 남자 = 오빠
* 손위 여자 = 언니

준호 기준:

* 손위 남자 = 형
* 손위 여자 = 누나

다음은 FAIL:

* 지은 기준 형
* 지은 기준 누나
* 준호 기준 오빠
* 준호 기준 언니

동일 인물의 호칭이 중간에 바뀌지 않았는지도 검사한다.

### E. 질문-응답 검사

1~5번째 라인의 모든 질문이 바로 다음 문장에서 답변되는가?

질문의 핵심 정보에 직접 답했는가?

### F. B2 TERMINAL CHECK

각 세트의 6번째 문장만 따로 다시 검사한다.

다음 중 하나라도 YES면 FAIL:

* 새로운 질문인가?
* `?`로 끝나는가?
* 상대방에게 추가 정보를 요구하는가?
* 새로운 부탁인가?
* 새로운 선택을 요구하는가?
* 새로운 제안에 대한 상대의 답이 필요한가?
* 새로운 화제를 시작하는가?
* 7번째 대사가 있어야 자연스러운가?

다음 질문에 반드시 YES여야 한다.

> 이 문장 뒤에서 대화가 바로 끝나도 자연스러운가?

NO이면 FAIL.

### G. 원어민 자연성 검사

각 세트 전체를 통째로 읽는다.

> 한국 원어민 두 사람이 실제로 이렇게 말할까?

다음이 있으면 FAIL:

* 번역투
* 설명체
* 지나친 교과서체
* 부자연스러운 이름 반복
* 부자연스러운 주어 반복
* 대화 리듬 단절
* 갑작스러운 화제 전환
* 맥락 없는 감정 표현
* 마지막이 덜 끝난 느낌

### H. TTS 검사

target 문장에:

* 아라비아 숫자
* 금지 기호
* 이모지
* 이모티콘
* 읽기 어려운 약어

가 없는가?

━━━━━━━━━━━━━━━━━━

## 21. 생성 전 내부 상태 초기화

━━━━━━━━━━━━━━━━━━

BATCH 실행이 시작되면 외부 대화 맥락의 화자 이름과 가족 설정을 모두 무시한다.

항상 다음 상태로 새로 시작한다.

`A = 지은 = 여성`

`B = 준호 = 남성`

가족 구성은 세트마다 새롭게 설정할 수 있다.

한 세트 안에서만 관계 일관성을 유지한다.
